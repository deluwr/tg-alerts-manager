# TG Alerts Manager

Принимает вебхуки Grafana и раскладывает алерты по темам (тредам) группы Telegram. Настраивается в веб-панели: бот, маршруты, формат сообщений, прокси, сертификат, бэкапы. Без зависимостей: Python из системы, xray для выхода в Telegram.

## Установка

На Linux с systemd (Ubuntu, Debian, RHEL-семейство), от root:

```bash
bash <(curl -fsSL https://github.com/deluwr/tg-alerts-manager/releases/latest/download/install.sh)
```

Установщик спросит логин и пароль панели (Enter — сгенерировать) и на что выпустить сертификат HTTPS:

1. **Let's Encrypt на IP сервера** — домен не нужен; сертификат на 6 дней, продлевается сам.
2. **Let's Encrypt на домен** — A-запись домена должна указывать прямо на сервер. Если домен за Cloudflare, прокси для этой записи нужно выключить (серое облако): Cloudflare не пропускает порты панели и вебхука.
3. **Самоподписанный** — браузер и Grafana будут предупреждать.

Порт 80 должен быть открыт снаружи — на нём Let's Encrypt проверяет сервер. В конце установщик покажет адрес панели и вебхука. Повторный запуск той же команды обновляет до последнего релиза; конфиг в `/var/lib/tg-alerts-manager` сохраняется.

Без вопросов (все переменные необязательные):

| Переменная | Что это |
|---|---|
| `PANEL_USER`, `PANEL_PASS` | логин и пароль панели |
| `TGAM_TLS` | `ip`, `domain` или `self` — на что выпускать сертификат |
| `DOMAIN` | домен для `TGAM_TLS=domain` |
| `BOT_TOKEN`, `CHAT_ID` | токен бота и id группы с темами |
| `VLESS` | ссылка `vless://…`, если Telegram с сервера напрямую недоступен |
| `PANEL_PORT`, `HOOK_PORT` | порты панели и вебхука, по умолчанию 1337 и 6969 |
| `TGAM_RESTORE` | файл бэкапа — восстановить конфиг сразу при установке |
| `TGAM_VERSION` | конкретный релиз, например `v1.0.0` |

```bash
PANEL_USER=ops PANEL_PASS='длинный-пароль' TGAM_TLS=domain DOMAIN=alerts.example.com \
  bash <(curl -fsSL https://github.com/deluwr/tg-alerts-manager/releases/latest/download/install.sh)
```

Сертификат можно поменять позже в разделе «сертификат» панели или командой `tgam cert`.

## Настройка

1. **Telegram.** Создайте бота у @BotFather, добавьте его в группу с включёнными темами. В панели укажите токен и chat_id группы. Чтобы узнать id, отправьте `/id` в нужной теме — бот ответит chat_id и thread_id, а тема появится в списках панели.
2. **Grafana.** Contact point → Webhook, метод POST, адрес вебхука из панели. Если задан секрет — заголовок `Authorization: Bearer <секрет>` (или `?token=<секрет>` в адресе). При самоподписанном сертификате включите в Grafana «Skip TLS verify».
3. **Маршруты.** Список, где каждый маршрут — одна строка: куда отправлять (темы, при желании ещё и General) и при каких labels. По клику открывается редактор: темы выбираются кнопками из тех, что бот уже видел, условия — label (`alertname`, `service`, `grafana_folder` или свой) и значения. Алерт должен совпасть со всеми условиями маршрута, значения внутри условия — любое из списка, `*` — маска. Срабатывает первый подходящий маршрут сверху вниз; порядок меняется перетаскиванием или стрелками. Ничего не подошло — тред по умолчанию.

## Бэкап и восстановление

В разделе «Бэкап» укажите id пользователя Telegram и интервал — бот будет присылать ему файл с конфигом (токен, маршруты, формат, VLESS, пароль панели). Получатель должен один раз написать боту `/start`; в ответ бот пришлёт свой id.

Восстановить: загрузить файл в разделе «Бэкап», либо на сервере `tgam restore файл.json`, либо при установке на новый сервер `TGAM_RESTORE=файл.json bash <(curl …)`.

## Обновление

Панель раз в несколько часов проверяет релизы на GitHub. Когда выходит новый, в шапке появляется «доступна vX», и в разделе «Панель» — кнопка «обновить». Обновление скачивает релиз, сверяет контрольную сумму и перезапускает сервис; конфиг не трогается. С консоли — `tgam update`.

## Команды на сервере

| Команда | Что делает |
|---|---|
| `tgam` | адрес панели и вебхука |
| `tgam update` | обновить до последнего релиза |
| `tgam password` | сменить логин и пароль панели |
| `tgam cert [--force]` | выпустить сертификат Let's Encrypt по текущим настройкам |
| `tgam restore <файл>` | восстановить конфиг из бэкапа |
| `tgam logs` | журнал сервиса |

## Как устроено

- `/opt/tg-alerts-manager` — программа, xray, certbot в своём venv; `/var/lib/tg-alerts-manager` — конфиг, сертификаты, журналы.
- Сервисы systemd: `tgam` (панель и вебхук), `tgam-xray` (локальный HTTP-прокси 127.0.0.1:17777 для Telegram), таймер `tgam-certbot-renew`.
- Сертификат Let's Encrypt выпускается через HTTP-01 (certbot ≥ 5.4 в своём venv, для IP — профиль shortlived): на время проверки служба на порту 80 останавливается и запускается обратно. Системный certbot и чужие сертификаты не затрагиваются.
